## 📘 Final 54

### คำถามแนว: อธิบาย 4 หลักการของ OOP

### เฉลย

**1. Encapsulation (การห่อหุ้มข้อมูล)**
- การซ่อนรายละเอียดภายในของ class โดยใช้ access specifier (`private`, `protected`, `public`)
- ป้องกันไม่ให้ภายนอกเข้าถึงหรือเปลี่ยนข้อมูลโดยตรง
- เข้าถึงผ่าน getter/setter method

```cpp
class BankAccount {
private:
    double balance;    // ซ่อนไว้ ภายนอกเข้าถึงไม่ได้
public:
    double getBalance() { return balance; }        // อ่านได้
    void deposit(double amt) { balance += amt; }   // เปลี่ยนผ่าน method
};
```

**2. Inheritance (การสืบทอด)**
- class ลูกสามารถรับ attributes และ methods จาก class แม่โดยไม่ต้องเขียนใหม่
- ส่งเสริม code reuse

```cpp
class Animal { public: void eat() { cout << "eating"; } };
class Dog : public Animal { public: void bark() { cout << "woof!"; } };
// Dog มีทั้ง eat() และ bark()
```

**3. Polymorphism (พหุสัณฐาน / หลายรูปแบบ)**
- ฟังก์ชันเดียวกันสามารถทำงานต่างกันขึ้นกับ object ที่เรียกใช้
- Compile-time: Function Overloading
- Runtime: Virtual Function

```cpp
class Shape { public: virtual double area() = 0; };
class Rect : public Shape { public: double area() { return w*h; } };
class Circle : public Shape { public: double area() { return 3.14*r*r; } };
// เรียก area() เดียวกัน แต่คำนวณต่างกัน!
```

**4. Abstraction (นามธรรม)**
- ซ่อนความซับซ้อนภายใน แสดงเฉพาะสิ่งที่ผู้ใช้ต้องรู้
- ใช้ abstract class / interface กำหนด "สัญญา" ว่า class ลูกต้อง implement อะไร

```cpp
class Shape {
public:
    virtual double area() = 0;  // กำหนดว่าทุก Shape ต้องคำนวณ area ได้
    // ไม่ต้องบอกว่า "คำนวณอย่างไร" → ให้ class ลูกกำหนดเอง
};
```

## 📘 Final 58

### คำถามแนว: อธิบายความแตกต่างระหว่าง Composition กับ Inheritance

### เฉลย

| หัวข้อ | Composition (Has-A) | Inheritance (Is-A) |
|--------|--------------------|--------------------|
| **ความสัมพันธ์** | "มี" (A มี B) | "เป็น" (A เป็น B ชนิดหนึ่ง) |
| **ตัวอย่าง** | Person มี Date, Address | Student เป็น Person |
| **วิธีเขียน** | ประกาศ object เป็น member | ใช้ `:` สืบทอด |
| **การเข้าถึง** | ผ่าน member object | เข้าถึง protected/public ของแม่ได้ |
| **ความยืดหยุ่น** | เปลี่ยน member ได้ง่าย | ผูกติดกับ class แม่ |
| **Coupling** | Loose coupling | Tight coupling |

```cpp
// Composition (Has-A)
class Car {
    Engine engine;       // Car "มี" Engine
    Wheel wheels[4];     // Car "มี" Wheel 4 ล้อ
};

// Inheritance (Is-A)
class ElectricCar : public Car {  // ElectricCar "เป็น" Car ชนิดหนึ่ง
    Battery battery;
};
```

**หลักการ:** ถ้าสงสัยระหว่าง Composition กับ Inheritance → **เลือก Composition** เพราะยืดหยุ่นกว่า (Favor Composition over Inheritance)

## 📘 Final 59

### คำถามแนว: อธิบาย Virtual Function และ Pure Virtual Function

### เฉลย

**Virtual Function:**
- ฟังก์ชันที่ประกาศด้วย keyword `virtual` ใน base class
- เปิดโอกาสให้ derived class **override** (เขียนทับ) ได้
- เมื่อเรียกผ่าน base class pointer/reference → จะเรียก method ของ **object จริง** (runtime binding)
- class ที่มี virtual function ยังสร้าง object ได้

```cpp
class Animal {
public:
    virtual void sound() { cout << "..." << endl; }  // มี body
};
// Animal a;  ✅ สร้างได้
```

**Pure Virtual Function:**
- Virtual function ที่ **ไม่มี body** ใช้ `= 0` ต่อท้าย
- class ที่มี pure virtual function เป็น **Abstract Class** → สร้าง object ไม่ได้
- บังคับให้ class ลูก **ต้อง implement** ถ้าต้องการสร้าง object ได้

```cpp
class Shape {
public:
    virtual double area() = 0;  // ไม่มี body → pure virtual
};
// Shape s;  ❌ สร้างไม่ได้!
```

| | Virtual Function | Pure Virtual Function |
|--|:-:|:-:|
| มี body | ✅ | ❌ (= 0) |
| สร้าง object ได้ | ✅ | ❌ (Abstract) |
| Override ได้ | ✅ (optional) | ✅ (บังคับ) |
| ใช้ runtime binding | ✅ | ✅ |

## 📘 Final 60

### คำถามแนว: อธิบาย Shallow Copy vs Deep Copy และ Rule of Three

### เฉลย

**Shallow Copy (ค่าเริ่มต้น):**
- คัดลอกค่าทุก member ตรงๆ (รวมถึง pointer)
- ถ้ามี pointer → 2 object จะชี้ไปที่ memory เดียวกัน
- อันตราย! เพราะ delete ตัวหนึ่ง → อีกตัวเข้าถึง memory ที่ถูกลบแล้ว (dangling pointer)

```
Object A: ptr ──→ [data: 10]
                     ↑
Object B: ptr ──────┘   ← ชี้ที่เดียวกัน!
```

**Deep Copy:**
- สร้าง memory ใหม่สำหรับ pointer แล้วคัดลอก **ค่า** ไม่ใช่ **address**
- แต่ละ object มี memory ของตัวเอง → ปลอดภัย

```
Object A: ptr ──→ [data: 10]
Object B: ptr ──→ [data: 10]   ← คนละที่กัน!
```

**Rule of Three:**
> ถ้า class มี dynamic memory (new/delete) → ต้องเขียนเอง 3 อย่าง:

1. **Destructor** — ลบ memory ที่จองไว้
2. **Copy Constructor** — สร้าง object ใหม่แบบ deep copy
3. **Assignment Operator (operator=)** — copy ค่าแบบ deep copy + ตรวจ self-assignment

```cpp
class MyClass {
    int* data;
public:
    MyClass(int v) : data(new int(v)) {}

    // 1. Destructor
    ~MyClass() { delete data; }

    // 2. Copy Constructor
    MyClass(const MyClass& other) : data(new int(*other.data)) {}

    // 3. Assignment Operator
    MyClass& operator=(const MyClass& other) {
        if (this != &other) {
            *data = *other.data;
        }
        return *this;
    }
};
```

## 📘 Final 74

### คำถามแนว: อธิบาย Diamond Problem และวิธีแก้ด้วย Virtual Inheritance

### เฉลย

**Diamond Problem:**
เกิดเมื่อ class D สืบทอดจาก B และ C ซึ่งทั้งสองสืบทอดจาก A เดียวกัน

```
        A
       / \
      B   C
       \ /
        D
```

**ปัญหา:** D จะมี data member ของ A อยู่ **2 ชุด** (ชุดหนึ่งจาก B, อีกชุดจาก C)
- เปลืองหน่วยความจำ
- เกิด ambiguity (ความกำกวม) เมื่อเรียกใช้ method ของ A

```cpp
// ❌ ไม่ใช้ virtual → มี Person 2 ชุด!
class Student : public Person { };
class Teacher : public Person { };
class TA : public Student, public Teacher { };
// TA มี Person 2 ชุด → TA.name จะเป็นของ Student หรือ Teacher?
```

**วิธีแก้: Virtual Inheritance**
```cpp
// ✅ ใช้ virtual → มี Person 1 ชุดเท่านั้น!
class Student : virtual public Person { };
class Teacher : virtual public Person { };
class TA : public Student, public Teacher { };
// TA มี Person 1 ชุด → ไม่มี ambiguity
```

**กฎสำคัญ:**
1. ใช้ `virtual` ที่ระดับกลาง (B, C) ไม่ใช่ที่ D
2. D ต้องเรียก constructor ของ A (virtual base) **โดยตรง**
3. Constructor ของ A ที่เรียกใน B, C จะ **ถูกข้ามไป** (เพราะ D เรียกเอง)

## 📘 Final 75

### คำถามแนว: อธิบาย Template และประโยชน์

### เฉลย

**Template** คือ mechanism ที่ช่วยให้เขียน function หรือ class ที่ **ทำงานได้กับหลาย data type** โดยไม่ต้องเขียนซ้ำ

**Function Template:**
```cpp
// แทนที่จะเขียนแยก:
int maxInt(int a, int b) { return (a > b) ? a : b; }
double maxDouble(double a, double b) { return (a > b) ? a : b; }

// เขียน template เดียว:
template <typename T>
T maxVal(T a, T b) {
    return (a > b) ? a : b;
}

// ใช้ได้กับทุก type:
cout << maxVal(3, 7);        // int
cout << maxVal(3.14, 2.71);  // double
cout << maxVal('a', 'z');    // char
```

**Class Template:**
```cpp
template <typename T>
class Stack {
    T arr[100];
    int top;
public:
    Stack() : top(-1) {}
    void push(T val) { arr[++top] = val; }
    T pop() { return arr[top--]; }
};

Stack<int> intStack;       // Stack ที่เก็บ int
Stack<string> strStack;    // Stack ที่เก็บ string
```

**ประโยชน์:**
1. **Code Reuse** — เขียนครั้งเดียว ใช้ได้หลาย type
2. **Type Safety** — compiler ตรวจ type ให้
3. **Performance** — ไม่มี overhead ของ runtime casting

## 📘 Final 76

### คำถามแนว: อธิบาย Operator Overloading พร้อมยกตัวอย่าง

### เฉลย

**Operator Overloading** คือการกำหนดพฤติกรรมของ operator (+, -, =, <<, >>, ==, ฯลฯ) ให้ทำงานกับ user-defined type (class ที่เราสร้างเอง)

**ทำไมต้อง Overload?**
- ปกติ `+` ใช้ได้กับ int, double → แต่ใช้กับ class ที่เราสร้างไม่ได้
- Overloading ทำให้ `a + b` ทำงานกับ class ของเราได้

**ตัวอย่าง: operator+ สำหรับ class Vector**
```cpp
class Vector {
    double x, y;
public:
    Vector(double x, double y) : x(x), y(y) {}

    // operator+ เป็น member function
    Vector operator+(const Vector& v) {
        return Vector(x + v.x, y + v.y);
    }

    // operator== เป็น member function
    bool operator==(const Vector& v) {
        return (x == v.x && y == v.y);
    }
};

Vector a(1, 2), b(3, 4);
Vector c = a + b;  // เรียก a.operator+(b) → c = (4, 6)
```

**ตัวอย่าง: operator<< เป็น global function**
```cpp
ostream& operator<<(ostream& os, const Vector& v) {
    os << "(" << v.x << ", " << v.y << ")";
    return os;
}
cout << c;  // Output: (4, 6)
```

**กฎสำคัญ:**

| Operator | ต้องเป็น | เหตุผล |
|----------|---------|--------|
| `=`, `[]`, `()`, `->` | Member function | ต้องเข้าถึง `this` |
| `<<`, `>>` | Global/Friend function | operand ซ้ายคือ ostream/istream |
| `+`, `-`, `*`, `==` | ได้ทั้งสอง | แล้วแต่ design |

## 📘 Final 77

### คำถามแนว: เปรียบเทียบ Compile-time Polymorphism กับ Runtime Polymorphism

### เฉลย

| หัวข้อ | Compile-time | Runtime |
|--------|:-----------:|:-------:|
| **ชื่ออื่น** | Static Polymorphism | Dynamic Polymorphism |
| **ตัดสินใจเมื่อไร** | ตอน compile | ตอน run |
| **วิธีการ** | Function Overloading, Operator Overloading, Template | Virtual Function |
| **Keyword** | ไม่ต้องใช้ | `virtual` |
| **ใช้ผ่าน** | object ตรง | pointer/reference ของ base class |
| **ความเร็ว** | เร็วกว่า (ตัดสินใจตอน compile) | ช้ากว่าเล็กน้อย (ต้อง lookup vtable) |

**Compile-time Polymorphism:**
```cpp
class Calc {
public:
    int add(int a, int b) { return a + b; }           // version 1
    double add(double a, double b) { return a + b; }  // version 2
    int add(int a, int b, int c) { return a+b+c; }    // version 3
};
// Compiler เลือก version ที่ถูกต้องตอน compile
```

**Runtime Polymorphism:**
```cpp
class Shape {
public:
    virtual double area() = 0;
};
class Rect : public Shape {
public:
    double area() { return w * h; }
};

Shape* s = new Rect(5, 10);
s->area();  // ตอน compile ไม่รู้ว่า s ชี้อะไร → ตอน run ค่อยตัดสินใจ
```
